# CRO & UX Audit — প্রদীপ কুমার আচার্য্য বই স্টোর

**Site:** https://pradipbooks.insforge.site  
**Date:** 2026-09-26  
**Method:** Mobile-first walkthrough (390×844) as a Bangladeshi book buyer — guest browsing → login → add to cart → checkout → order placed (COD ৳750, Order `0af77bbe-4f72-4cc1-a936-b3c303f9987b`) → order history verified. Backend/DB/logs inspected directly.

---

## 1. Critical Conversion Blockers (Severity-1)

### 1.1 🛒 Cart is lost the moment a guest logs in
- **Evidence:** Guest added Paperback ৳750 → stored in `localStorage["bookstore-cart-guest"]`. After login the app switches to `bookstore-cart-<userUUID>` **without migrating** the guest cart → user cart was `[]`, navbar badge showed **1** while checkout said **"কার্টে কোনো আইটেম নেই"**.
- **Why it kills conversion:** Login is the highest-intent step; the customer sees a *contradiction* (badge=1, cart=empty) at the exact moment of commitment. Many will abandon silently.
- **Fix:** On successful login, merge `bookstore-cart-guest` into the user key (union by `bookId+format`, max qty), then remove the guest key. Same on logout (reverse-merge optional).

### 1.2 🔴 Product page serves a permanent "পাওয়া যায়নি" (soft-404) after one transient DB error
- **Evidence:** `/book/chhera-pushpo` flapped between full content and a *"পাওয়া যায়নি"* page, then stayed stuck 404 for 15+ minutes (title = "বই পাওয়া যায়নি") while:
  - DB had exactly 1 row; local SDK loop succeeded 8/8; app-server API calls returned **HTTP 200 with the row**;
  - every homepage CTA, `BookCard` link, and the hardcoded hero link dead-ended there;
  - the page returned **HTTP 200** for a not-found body (**soft 404** — SEO hazard too).
- **Root cause:** `getCachedBookById` (`lib/public-cache.ts:39-43`) wraps `getBookById` in `unstable_cache(..., { revalidate: 60 })`. In **Next 16.3.2 `unstable_cache` is deprecated/replaced by `use cache`** and the `revalidate: 60` was **not** expiring the entry — a **transient `null` got baked and stayed forever**. `getBookById` (`lib/api.ts:155`) swallows all errors (`if (error || !data) return null`), so the failure was invisible.
- **Temporary mitigation applied:** admin PUT re-save → `invalidateBooks()` (`revalidateTag("books")` + `revalidatePath`) flushed it; page healthy again (re-verified after 20 min).
- **Fix (must-do):**
  1. Stop caching not-found/error results — only cache successful rows.
  2. Replace `unstable_cache` with Next 16 `use cache` + `revalidateTag`, or drop caching for the single-book read (it's one lightweight query).
  3. `console.error` the real error in `getBookById` before returning null.
  4. Return a true HTTP 404 (verify `notFound()` status; today it's 200).

### 1.3 🐌 Account/checkout surfaces feel broken because auth bootstrap takes 4–10s
- **Evidence:** `/api/auth/check-admin` alone took **2,183 ms**; flow is serial: `/api/profile` → `/api/auth/check-admin` → page-level `/api/my-orders` → layout counts (3 more fetches). `/account/orders` showed **only skeletons for 3–9 s** (first probe at 2.5–3.5 s showed nothing; resolved by ~9–12 s). Checkout briefly flashed the empty-cart state before the form appeared.
- **Why it matters:** On checkout, "কার্টে কোনো আইটেম নেই" flashing = trust-destroying even for a frame; customers interpret skeletons as "site broken".
- **Fix:** Run `fetchProfile` + `fetchAdminStatus` in parallel (or bake `isAdmin` into the profile response); cache admin status in the session cookie; render the checkout cart synchronously from localStorage (no flash).

## 3. Trust Gaps (Bangladeshi buyer expectations)

1. **No phone number / WhatsApp anywhere** — BD shoppers expect a call option before prepaid/COD orders.
2. **No payment-method logos or COD badge** on homepage, product, or checkout (bKash/Nagad/Rocket/COD are only mentioned as small text at checkout).
3. **No return/refund/exchange policy** linked near purchase CTAs (footer has only যোগাযোগ + গোপনীয়তা নীতি).
4. **No delivery-time promise** — only "৳৭৫০+ ফ্রি ডেলিভারি". Buyers ask "কবে পাব?" first.
5. **Zero reviews/ratings/social proof** — no reader testimonials, no "X কপি বিক্রি" counters.
6. **ISBN = null**, publisher date present — bibliophiles check ISBN.
7. **Single-book catalog** (1 book, shown in Featured/New/Trending) — store feels like a demo; needs an honest "coming soon" shelf.
8. **No urgency/offer**: `compare_at_price` null on both formats, no launch discount, no stock note.
9. **SEO/social**: `og:image` missing, `canonical` missing, `<h1>` is the author's name (not the store/value prop), homepage meta description is book-specific.
10. **Homepage has no phone, no address, no trust strip** above the fold.

## 6. Technical Recommendations

1. **Cache (P0):** Remove `unstable_cache` for `getCachedBookById` or migrate to Next 16 `use cache` + explicit `revalidateTag`; **never cache null/error results**; add `console.error(err)` in `getBookById` before returning null. Verify not-found returns real **HTTP 404**.
2. **Cart persistence (P0):** Single source of truth for cart key; merge guest→user on login (and guard against double-counting).
3. **Auth perf (P1):** Parallelize `/api/profile` + `/api/auth/check-admin` (2.2 s!), or include `isAdmin` in profile response; consider short-lived cookie caching.
4. **Session UX (P1):** Honor `?next=` redirect after login; prefill checkout from profile/saved addresses.
5. **Input quality (P1):** Add `autocomplete` (`name`, `email`, `tel`, `street-address`, `postal-code`), `inputMode=numeric` + regex hint for BD phone (`^01[3-9]\d{8}$`).
6. **SEO/meta (P2):** Add `og:image` (book cover), `<link rel=canonical>`, descriptive store-level `<h1>`, `og:type=product` on book pages, JSON-LD already present ✓.
7. **Observability (P2):** The 404 stayed invisible because errors are swallowed and only backend access logs exist — add error logging/alerts (e.g. Sentry) for data-fetch failures.
8. **Tests (P2):** Unit-test cart-merge on login; smoke-test that `/book/[id]` returns 404-status-vs-200 correctly; add a cache-poisoning regression test (null must not be cached).
